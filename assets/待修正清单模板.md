| # | 位置（合并稿行号） | 所属小节 | 来源分册 | 建议表名 |
|---|---|---|---|---|
| E1 | L… | （小节号） | （分册名:行号） | 表 X-Y … |
| E2 | | | | |

> **补名后果**：补名只加题注、不改正文内容，但会触发全篇表号重排——编号由构建脚本的 `plan_numbers()` 按出现顺序自动重排，**无需手工改号**，但重排后须重跑一次禁用词与编号连续性校验。

## 二次修正机制（本清单如何滚动）

本清单是**活文档**，每轮修正后更新：

1. **修一条、销一条**——A/B/C 类每条后面加状态标记：`[ ] 待修` / `[~] 修中` / `[x] 已修（日期）`；
2. **新增问题进清单**——二次修正中新发现的问题，按 A/B/C/D/E 归类补入，不要口头记；
3. **口径变更进第二节**——任何「改口径」的决定，写进第二节，注明日期与依据；
4. **D 类只减不增**——资料每到位一批，D 类条目就少一批；新增 D 类要有充分理由；
5. **基线对比**——每轮体检后把 `compliance.json` 存为 `compliance_prev.json`，
   下一轮用 `--prev` 对比，确认「新增 = 0」；
6. **全清条件**——A/B 类清零 + D 类〔初稿注〕删净 + E 类补名完成 = 可转报审稿。

> 见《二次修正流程.md》第 2、3 节。
