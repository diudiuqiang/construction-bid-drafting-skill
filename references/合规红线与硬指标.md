# 合规红线与硬指标

> 本文件定义「什么算红线」「什么必须显性写出」，是**体检模式的口径来源**，也是编制模式的写作目标。
> 两者是同一件事的两面：编制时按本文件写，体检时按本文件查。

---

## 1 评标口径决定一切

动笔前先锁定评标办法，它决定全篇的写法方向。

| 评标办法 | 技术标性质 | 写法方向 | 风险点 |
|---|---|---|---|
| 澄清低价法 + 合格制 | 不打分，只做符合性审查 | **零硬伤、无无关内容**；写得「对」比写得「多」重要 | 堆砌无关内容 → 直接不通过 |
| 综合评估法 + 打分制 | 按要点打分 | 多点得分项、突出重难点与亮点 | 漏项 → 失分 |

> **合格制的三条否决标准**（原文通常长这样）：
> ① 无与本项目无关内容；② 须与现场实际工况相匹配；③ 不存在明显不合理或过于简单粗略（或过于繁复堆砌）。
> 这三条是**否决项**，一处硬伤即不通过，**不能靠事后澄清补救**。

**前附表里的「不允许偏差」条款**要单独标红。合格制 + 不允许偏差 = 任何条件性表述（「如招标人要求则…」「是否…待定」）本身就是偏差。

## 2 通过标准 → 章节映射（零漏项）

把通过标准逐条拆成可检查的节点，每个节点映射到具体章节。**映射表是自检表的骨架**。

| 通过标准原文 | 映射节点 | 落点要求 |
|---|---|---|
| 要素齐全、满足高峰期人员及施工要求 | 总平面布置、临电临水、现场条件 | 八要素齐 + 高峰期校核 |
| 关键线路标示清晰 | 进度章节 + 网络图说明 | **双重出现**（两处都写） |
| 与现场实际工况相匹配 | 每章 | 每章至少 1 句实景锚点 |
| 不过于繁复堆砌 | 全篇 | 与项目无关的整章删除 |
| 规范符合性 | 规范清单 + 验收章节 | **无已废止规范** |
| 危大工程识别及管理 | 安全章节 | 独立清单，不得缺项 |

> **「双重出现」的含义**：某些硬指标要求在同一份文件里出现两次（例如进度章节文字说明一次、网络图/横道图说明再一次）。
> 只写一次会被判「不清晰」。自检时必须确认两处都在。

## 3 A/B/C/D/E 五类问题分类

| 类 | 名称 | 判定标准 | 处理方式 |
|---|---|---|---|
| **A** | 必须修正（红线） | 禁用词命中、疑似废止规范、硬指标缺失、结构断裂、AI 痕迹 bad 级 | **不得提交**，逐项修正后复检 |
| **B** | 应当修正 | 编号缺号/不连续、缺表名表格、格式残留、初稿注超限 | 按清单处理 |
| **C** | 建议优化 | AI 痕迹 warn 级、风格统一性 | 参照 AI 痕迹消解手册 |
| **D** | 待澄清 | `〔初稿注〕` 内容 | 待勘察/设计/业主资料到位后统一替换 |
| **E** | 提示 | 篇幅统计、一致性建议 | 人工复核 |

**状态判定**：A 类非空 → `fail`；B/C 非空 → `warn`；否则 `pass`。

### 3.1 A 类细目

| 细目 | 判定 | 说明 |
|---|---|---|
| 禁用词 | 正则命中 | 见 3.3 前缀剥离规则 |
| 疑似废止规范 | 版本号年份 < 2008 | 白名单除外（如 JGJ 46-2005 现行有效） |
| 硬指标缺失 | 关键字符串未在全文出现 | 从 `conf/硬指标.txt` 读 |
| 结构断裂 | 标题层级跳跃、编号重复、编号不衔接 | 由结构审计给出 |
| AI 痕迹 bad | 高置信套话/空话/半角标点/感叹号/段长句长过于均匀 | 见 AI 痕迹手册 |

### 3.2 禁用词的前缀剥离（重要）

「不配置储能」是**正确表述**，但「储能」在禁用词表里。直接扫描会误报。

**规则**：扫描前先把「否定前缀 + 禁用词」整体替换为空格，再扫描。

```
不配置储能    → （剥离）
不设储能      → （剥离）
无储能        → （剥离）
不涉及储能    → （剥离）
不含储能      → （剥离）
不作储能      → （剥离）
不采用储能    → （剥离）
不再储能      → （剥离）
```

> **注意**：前缀剥离只对「本项目明确不做的系统/工艺」这类否定表述有效。
> 如果正文里出现「储能」而**没有**否定前缀，就是真命中，必须删除。
> 前缀列表可在 `compliance_check.py` 的 `classify()` 里调整。

### 3.3 硬指标缺失的判定陷阱

- **关键字符串要选得「只能出现在正确表述里」**。例如硬指标「按自然月」，关键字符串写「按自然月」而不是「自然月」（后者可能出现在「自然月降水量」里）。
- **同一硬指标可能有两种正确写法**（如「12 小时内到达现场」vs「12h 内到达现场」）。此时应拆成两条硬指标，或改用更宽松的字符串。
- 硬指标缺失会误报的情况：该内容确实写了，但措辞与关键字符串不同。**误报比漏报好**——人工复核即可。

## 4 硬指标清单（11 项）

以下是合格制技术标最常见的硬指标。**按项目裁剪**，不要照单全收。

| # | 硬指标 | 关键字符串示例 | 易漏点 |
|---|---|---|---|
| 1 | 无已废止规范 | `现行有效` / `无已废止` | 全篇声明缺失，或规范清单混入旧版号 |
| 2 | 总平面八要素满足高峰期 | `高峰期` + 八要素名 | 只列要素不做高峰期校核 |
| 3 | 关键线路标示清晰【双重】 | `关键线路` | 只写一次；网络图里没标 |
| 4 | 危大工程清单 | `危大工程` | 只有识别没有清单，或清单缺项 |
| 5 | 机械配置表含年份 | `年份` / 具体年份数字 | 表头漏「年份」列 |
| 6 | 按自然月劳动力 + 各工种 + 高峰总人数 | `按自然月` / `高峰` | 只给总工日，不按月份分解 |
| 7 | 高标准鱼塘含尾水【双重】 | `尾水` | 只写鱼塘不写尾水；只写一次 |
| 8 | 设备五要素 | 五要素关键词 | 缺技术服务或质保期 |
| 9 | 材料进场四字段 | 名称/规格/数量/时间 | 缺时间或规格 |
| 10 | 人员资格证书有效期内 | `有效期` | 只列证书不提有效期 |
| 11 | 保修 12h/24h/任一条件/金额 | `12` `24` `任一` | 数字改写或漏「任一条件」 |

> **「双重出现」的硬指标**（3、7）是最容易漏的。自检时数次数，不要只看有没有。

## 5 conf 文件怎么建

项目专属内容**一律走外部文件**，脚本只放通用方法。这样同一套脚本能服务不同项目。

```
项目工作目录/
├── conf/
│   ├── 禁用词.txt        # 每行一条正则
│   ├── 硬指标.txt        # 每行「指标名: 关键字符串」
│   ├── 措辞归一.txt      # 每行「原文 ==> 替换」
│   ├── cross_ref.json    # 跨分册表/图号映射
│   ├── banner.md         # 文首横幅（项目名/文档名）
│   └── meta.json         # docx 元数据（作者/主题/关键词）
├── draft/                # 分册 pNN-M.md
└── out/                  # 合并稿、docx、体检报告
```

### 5.1 `conf/禁用词.txt`

```
# 每行一条正则，# 开头为注释
# 其他项目的地名/项目名
长丰|合肥|下塘|杜集|安徽|九江|九江县|赛城湖|江西
# 其他项目的容量
70MW|50MW|100MW|20MW
# 其他项目的电压/系统
220kV|110kV|35kV|储能|SVG|主变|风电升压站|铁塔|跨越架|抽水蓄能
# 其他项目的工艺
钻孔灌注桩|清淤|膨胀土
# 其他项目的日期
240日历天|2016年1月10日|2017年10月
```

**要点**：
- 用 `|` 合并同组词，减少行数。
- 词要选「只可能出现在错误内容里」的。太宽的词（如「主变」）可能误伤正确表述。
- 本项目明确不做的系统（如储能），靠 3.2 的前缀剥离处理，不靠禁用词表。

### 5.2 `conf/硬指标.txt`

```
# 每行「指标名: 关键字符串」，分隔符可以是 : ： = 空格
无已废止规范: 现行有效
关键线路: 关键线路:2
危大工程: 危大工程
机械年份: 年份
按自然月: 按自然月
高峰总人数: 高峰
高标准鱼塘尾水: 尾水:2
设备五要素: 技术服务
材料四字段: 规格
证书有效期: 有效期
保修时限: 12
保修扣罚: 任一条件
```

**要点**：
- 关键字符串选**最短且唯一**的片段。
- 同一硬指标多种写法时拆成多条，或选更短的公共片段。
- **`:N` 后缀声明最少出现次数**（如 `关键线路: 关键线路:2`）。
  标注【双重】的硬指标必须写次数，否则脚本只判「有没有」，写一次也算过。
  实测提示写法：`需 ≥2 处，实际 1 处`。

### 5.3 `conf/cross_ref.json`

跨分册的表/图号映射。各分册内部用本地流水号，合并时重排为全篇统一号，跨册引用靠本文件解析。

```json
{
  "p05-1.md|表|3|1": ["p03-2.md", "表", 3, 15],
  "p05-2.md|图|3|4": ["p03-2.md", "图", 3, 9]
}
```

键格式：`分册文件名|类型|章|册内号`；值格式：`[目标分册, 类型, 章, 目标号]`。

### 5.4 `conf/meta.json`

```json
{
  "title": "施工方案（技术标第十章）",
  "creator": "投标技术组",
  "subject": "横沙乡 5.76MW 渔光互补发电项目 EPC 总承包",
  "keywords": "施工方案,技术标,渔光互补,光伏",
  "footer": "第 页",
  "application": "Microsoft Office Word"
}
```

> **`creator` 和 `application` 是工具痕迹的重灾区**，详见《AI痕迹识别与消解.md》。

## 6 体检命令

```bash
python scripts/compliance_check.py \
    --in ./out/施工方案.md \
    --banned ./conf/禁用词.txt \
    --hard ./conf/硬指标.txt \
    --notes-limit 10 \
    --prev ./out/compliance_prev.json \
    --report ./out/compliance.json \
    --md ./out/合规体检报告.md
```

| 参数 | 作用 |
|---|---|
| `--in` | 待检文件（md 或 docx，按扩展名自动识别） |
| `--banned` | 禁用词文件 |
| `--hard` | 硬指标文件 |
| `--notes-limit` | 初稿注上限，默认 10 |
| `--prev` | 上次体检的 JSON，用于基线对比 |
| `--report` | 输出 JSON 报告（下次作为 `--prev`） |
| `--md` | 输出 Markdown 报告 |
| `--quiet` | 只输出摘要 JSON |

**退出码**：`pass` → 0；`warn` / `fail` → 非 0。

## 7 基线对比（二次修正的核心）

每次体检后保留 JSON 报告，下次作为 `--prev` 传入，得到三类变化：

| 变化 | 含义 | 处理 |
|---|---|---|
| **新增** | 上次没有、这次出现 | ⚠️ 最危险——说明修改引入了新问题，逐项回退或修正 |
| **已修复** | 上次有、这次没有 | ✅ 确认修复到位 |
| **遗留** | 两次都有 | 持续跟踪，下次必须处理 |

**指纹格式**：`类别|类型|详情`。

> **使用铁律**：
> ① 每次体检后**立即把 JSON 存档**（改名带日期），否则下次没有基线；
> ② 新增问题必须逐项说明原因，**不允许「修改引入的新问题」沉默放过**；
> ③ 基线文件放在 `out/` 下，不要放进 `draft/`。

## 8. 常见误判与人工复核

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 禁用词命中但内容正确 | 前缀剥离未覆盖该否定式 | 补前缀列表，不删内容 |
| 硬指标缺失但正文其实写了 | 关键字符串选得太严 | 放宽字符串 |
| 结构断裂告警 | 分册片段不含文首横幅 | 用 `--segments` 模式或 `allow_start_any` |
| 编号缺号 | 分册本地编号撞号 | 合并后校验，分册阶段跳过 |
| AI 痕迹 bad 但文本正常 | 短文本统计失真 | 人工复核，不盲改 |
