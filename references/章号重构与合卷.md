# 章号重构与合卷

## 0. 什么时候会用到

编制阶段的章号是**按写作顺序**排的（例如 3 施工部署、4 采购、5 项目管理、6 现场条件、7 保修、8 响应时限）。
而招标文件常在「投标文件组成」里**另行规定**交付章号：第十章施工方案、第十一章工程总承包管理方案、第十二章采购方案、第十三章其他技术标资料。

于是投标截止前要做一次**合卷**：把已写好的正文按招标规定的章号重新组织、重编号、重排表图号，同时尽量不丢内容。
这不是「再写一遍」，是**只改编号层的一次性变换**。

> 触发信号：用户说「按招标文件第 X 页的结构重新组织」「把几章合成一册」「章号要改成十/十一/十二/十三」「出终稿」。

**适用边界**：本文件只讲编号变换与结构对齐，**项目专属的映射表、禁用词、工期人数一律放项目 `conf/`，不写进 skill**。

---

## 1. 五步流程

| 步 | 做什么 | 产物 |
|---|---|---|
| 1 | 建 `CH_MAP`：旧顶层章号 → 招标规定章号 | 项目配置（如 `conf/chapter_map.json`） |
| 2 | 收集 `SECTION_NUMS` 白名单：源文件**标题里出现过的带点章节号** | 内存集合 |
| 3 | `remap_headings`：改写所有标题行开头的章节号 | 变换后的正文 |
| 4 | `remap_refs`：改写正文里的「见 3.1.4」「与 4.2 对应」等交叉引用 | 变换后的正文 |
| 5 | 表号/图号按**新顶层章号**两遍法全局重排 | 终稿 md |

顺序不能乱：先改标题、再改引用、最后重排表图号。表图号重排必须放在最后，否则新插入的表会打乱计数。

### 第 1 步的坑：新章号可能含小数

招标规定的章号常出现 `13.1 / 13.2 / 13.3` 这类小节号。若代码里对章号做 `int(ch)`，会直接抛
`ValueError: invalid literal for int() with base 10: '13.1'`。

**表号前缀与计数器键一律取顶层章号**：

```python
top = CH_MAP.get(str(ch), str(ch)).split('.')[0]
ck = (kind, top)
counters[ck] = counters.get(ck, 0) + 1
return '%s %s-%d' % (kind, top, counters[ck])
```

否则「表 13.1-1」这种号既不规范，也会让计数器和前缀对不上。

### 第 2 步的坑：白名单只收带点章节号

`SECTION_NUMS` 用来判断「这个数字串是不是章节号」。**只收源文件标题里出现过的、带点的编号**（`3.1`、`3.1.4`、`4.2` 等）。
**不要把裸章号（`3`、`4`、`5`…）放进去**——见第 2 节第一个坑。

## 2. 三个实测踩过的坑

### 坑一：裸数字误伤（最严重、最隐蔽）

**症状**：合卷后正文里出现「表 3-12」「表 3-13.1」「第 12 月」「13.3 个塘级流水段」「| 13.1 |」这类荒谬文本。
体检脚本可能全绿，因为表号本身是连续的——错的是**正文里的普通数字被替换了**。

**根因**：`remap_refs` 用正则找数字串并查 `CH_MAP`。像 `表 3-4` 里的 `4`、`第 4 月` 里的 `4`、
表格行首序号 `6`、`8 个流水段` 里的 `8`，都会被当成「旧章号」映射成 `12 / 13.1 / 13.3`。
早期写的负向断言只挡了「后接 `-数字`」，没挡「**前接** `-数字`」的第二个数字。

**解法（三条一起上）**：

1. 正则 lookbehind 加 `\-`：

   ```python
   CH_REF_PAT = re.compile(
       r'(?<![\d.\-])(\d{1,2}(?:\.\d{1,2}){0,3})(?![\d.]|\s*-\s*\d)')
   ```

2. **`remap_refs` 只处理带点的 token**。裸章号引用（「第 4 章」「见第 8 章」）数量有限且可枚举，
   由变换表**显式逐条替换**，不要交给通用正则：

   ```python
   def remap_refs(text):
       def repl(m):
           tok = m.group(1)
           if '.' not in tok or tok not in SECTION_NUMS:
               return tok
           lead = tok.split('.')[0]
           if lead not in CH_MAP:
               return tok
           return CH_MAP[lead] + '.' + tok.split('.', 1)[1]
       return CH_REF_PAT.sub(repl, text)
   ```

3. 显式替换后 **grep 一遍**裸章号引用，确认无遗漏：

   ```bash
   grep -nE '第 ?[0-9]+ ?章|见 ?[0-9]+ ?章' 终稿.md
   ```

**为什么小数、参数不会误伤**：`5.76 / 5.9995 / 0.55 / 1.11.2 / 8.7 / -21°` 等虽然带点，
但不在 `SECTION_NUMS` 白名单里，直接原样返回。白名单是第二道保险。

### 坑二：替换区间起点歧义，误删标题和图

**症状**：合卷后某一节标题不见了，紧随其后的「图 X-Y」两行也没了，表号整体错位。

**根因**：用 `replace_span(text, start, end, new)` 做整段替换时，`start` 写成了表名，例如
`表 3-5 里程碑与控制节点表`。这个字符串**第一次出现是在上一段的正文引用里**
（「汇总见 3.1.4.2 表 3-5…」），不是表格标题行。于是替换区间从引用处一路吞到表格第 6 行，
把中间的 `#### 3.1.4.2` 标题和两张图的图名行一并删掉。

**解法**：`start` 必须**带上下一行的表头**，足以唯一定位表格定义处：

```python
start = '表 3-5 里程碑与控制节点表\n\n| 序号 | 里程碑控制节点 |'
```

并且替换前先断言 `text.count(start) == 1`；不是 1 就停下来改判据，别硬替。

### 坑三：标题整体上移一级

**症状**：合卷后合规体检报 A 类「标题对仗 H2 级 75%」，但四个章名是招标文件**规定**的，
三个以「方案」结尾，改不得。

**根因**：AI 痕迹检测把「同级标题结尾 2 字重复率」当模板化特征。招标规定的固定章名恰好撞上。

**解法**：不是改文案，而是**改层级结构**。把正文标题整体上移一级，让章级标题成为大纲顶层
（与封面 banner 同级），同级重复率自然降下来：

```python
def shift_headings(text):
    out = []
    for line in text.split('\n'):
        out.append(line[1:] if re.match(r'^#{2,6}\s+', line) else line)
    return '\n'.join(out)
```

Word 样式映射随之调整：`lv==1` 时数字开头 → `Heading1`、非数字开头（banner）→ `Title`；
`lv>=2` → `Heading{1..4}`。**层级仍按 `#` 级数判定，不按编号深度**（见 `Word标题层级规范.md`）。

> 这也是「校验器误判边界」的典型案例：
> **合规要求的固定措辞，不得为了降低 AI 痕迹评分而改写**。见 `校验器维护与误判边界.md`。

## 3. 表图号重排

沿用 `merge_validate.py` 的两遍法，只改一处：**全局号的章号前缀取 `CH_MAP` 映射后的顶层章号**。

- `plan_numbers()`：扫全文，为每个「首次出现的 (类型, 章号, 局部序号)」分配全局连续号；
- `apply_numbers()`：把正文里所有局部号替换为全局号。

注意 `seen` 集合是**每个文件独立**的；同一个 `(kind, ch, seq)` 在不同文件里会得到不同全局号，这是设计如此，不是 bug。

重排后必查：

```bash
# 表号 / 图号是否连续、无缺口、无重复
grep -oE '(表|图) [0-9]+-[0-9]+' 终稿.md | sort -u | wc -l
```

再对照 `out/build_report.json` 里记录的旧号 → 新号映射，逐项核对**关键表**（施工设备表、
试验检测仪器表、机械进退场表、劳动力表、材料储备表、资源匹配总校核表）没有串位。

## 4. 交叉引用（CROSS_REF）

合卷会放大 `cross_ref.json` 漏登记的后果：漏一条，图号或表号会**整体偏移 1~2 位**，
并产生悬空引用。合卷前先确认：

- `conf/cross_ref.json` 非空，且覆盖所有跨册引用；
- **分册里绝不能手写未登记的「表 X-Y / 图 X-Y」局部号**——两遍法会把它当成新定义占号，
  造成全篇表号后移 + 悬空引用。要引用别册的表，写章节文字，或登记进 `cross_ref.json`；
- 合卷后跑 `compliance_check.py` 的悬空引用检测，应为 0。

## 5. 交付前检查清单

- [ ] `CH_MAP` 覆盖全部旧顶层章号，新章号含小数时前缀取 `.split('.')[0]`
- [ ] 正文里没有「第 12 月」「13.3 个」「| 13.1 |」这类裸数字误伤残留
- [ ] 裸章号引用已逐条显式替换，grep 无遗漏
- [ ] 所有 `replace_span` 的 `start` 唯一（count == 1）
- [ ] 章节标题数、层级分布与合卷前一致（标题没被误删）
- [ ] 表号/图号连续，关键表逐项核对无串位
- [ ] 悬空引用 0、禁用词 0、硬指标缺项 0、初稿注 ≤ 上限
- [ ] 结构审计 `pass`、合规体检 A 类 0 且「新增」为 0（对比上一轮基线）
- [ ] docx `--verify` 通过；若含图片，再跑视觉终检（见 `Word图表混排与视觉终检.md`）

---

## 6. 一句话判据

> 合卷只动编号层，不动事实层。凡是「数字被改坏了」，先怀疑正则把裸数字当章节号；
> 凡是「内容少了一块」，先怀疑替换区间起点撞上了正文引用。
